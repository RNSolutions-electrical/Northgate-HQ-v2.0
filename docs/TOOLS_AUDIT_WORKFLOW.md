# Tools Catalogue Audit Workflow

Production pass, September 6, 2026. The compact catalogue and dedicated add/edit
module are preserved. This is catalogue maintenance, not a new custody workflow.

## Behavior

- Add a normal tool without an audit reason. Operational Notes remain tool data.
- Save existing catalogue edits with one reason for all changed fields, collected
  in a dialog after Save. Entering a new tool as retired also requires a reason.
- Archive and restore both require a reason in the same dialog pattern. Archive
  reason no longer occupies the edit form. Cancelling leaves the draft unchanged.
- Failed mutations retain the form and dialog reason. A stale record is rejected;
  refresh/reopen to review the latest version rather than silently overwriting it.
- Restore an archived tool before editing its catalogue fields.

## Server Contract

`save_tool_catalogue` is SECURITY INVOKER, fixed empty search path, authenticated
only. Existing tools RLS remains in force. It accepts only catalogue fields and
save/archive/restore actions, checks permissions, locks existing rows, requires
their expected timestamp, normalizes reasons and rejects unsupported metadata.
Actor, archive time and audit snapshots are generated by the server.

`audit_tool_catalogue_mutation` is a non-client-callable SECURITY DEFINER trigger,
with empty search path, that writes protected change_logs within the same database
transaction. It enforces the scoped workflow and reasons, and prevents identity/
division mutation. The RPC restores its transaction-local context after success;
errors roll back the entire write, including audit. Failed audits cannot leave
partially saved tools. No audit-table write privilege or RLS relaxation is added.

Older direct-write clients now receive a refresh/current-workflow error. No real
tool values are rewritten by migration `20260906204812_tool_catalogue_audit_workflow`.
Checkout/return exemptions belong to their own future approved workflow, not to
manual edits of catalogue location/assignment text.

## Manual Acceptance

1. Refresh Tools and add a tool normally; no reason prompt should appear.
2. Edit multiple fields, press Save, and supply one reason. Check History.
3. Archive and restore with reasons; check both history entries.

Remaining module audit conversions and multi-record reason coverage stay in
`docs/APPROVED_WORKFLOWS.md`. This pass does not complete the sitewide rollout.
