# Scorecard bulk CSV contract v1

Staging implementation contract. One row per actual observation; missing rows never delete. UTF-8 CSV, quoted fields/multiline Notes supported. Exact headers (order may vary):

`Metric,Date,Value,Notes,Format,Review,Source,System reference`

The normal user edits Value and Notes only. HQ supplies every other field on export. New initial-history rows may be prepared programmatically from the preserved source copy; no manual UUIDs, Monday calculations or action flags.

- **Metric:** exact historical metric name, case-sensitive. No guessed/fuzzy matches. New unreferenced rows require exactly one existing definition with this name effective at the week containing Date; ambiguous/missing definitions need review.
- **Date:** ISO `YYYY-MM-DD`, original source meeting date for initial rows. HQ computes Monday anchor internally. Existing reference-backed rows cannot change Metric/Date/Format/Review/Source; only Value/Notes are editable. Internally preserve the existing definition, measurement dates, source meeting date, provenance and review state.
- **Value:** unformatted finite number; `count` requires whole numbers; `text` retains text. For `percent`, values are in 0–100 and an optional trailing `%` is accepted (`12.5` or `12.5%` both mean12.5%). Never infer workbook fraction scale. Initial conversion must deliberately convert workbook fractions to0–100 before generating this CSV. Zero is an actual. Blank means preserve existing value; on a new row it supplies no actual.
- **Notes:** plain source comments/text. Blank preserves existing notes. Clearing values/notes is deliberately outside bulk editing; use the normal editor for explicit clears. New rows with Notes but no Value may create a notes-only observation when all metadata is complete; completely blank new rows are unchanged.
- **Format:** exact `number`, `count`, `currency`, `percent`, or `text`; must match the effective definition. It does not assign/change a definition or unit.
- **Review:** human-readable `Needs review` or `Reviewed` for new rows (legacy `review-needed`/`reviewed` also accepted). `Needs review` records provisional source status and DOES NOT block an otherwise valid row. It is distinct from validation conflicts in the preview's Needs review group. Exports may use `Preserved` when no structured historical review metadata exists; keep it unchanged. No bulk changes to review state.
- **Source:** JSON text in one CSV field, generated by preparation/HQ, never manually assembled by the ordinary user. Accepted string properties: required `id` (workbook name/stable source identity), `revision`, `cell` (sheet!cell); optional `url`, `meeting_date`, `measurement_start`, `as_of`. No other keys. For a confirmed point-in-time definition only, omitted dates use the original Date for start/as_of/meeting_date. Other windows require explicit source measurement dates; uncertain weekly intervals are held, not inferred. Explicit meeting_date must equal Date; start<=as_of. Example: `{"id":"synthetic-fixture.xlsx","revision":"v1","cell":"Sheet!B4","url":"https://example.invalid/source","meeting_date":"2026-01-06","measurement_start":"2026-01-01","as_of":"2026-01-06"}`. QTD/YTD dates must follow a confirmed definition during preparation. Existing exports carry a machine-owned object which must not change.
- **System reference:** opaque server-issued export/row reference; leave untouched. A referenced edit must match the authenticated export owner's stored baseline and current revisions/definition. It cannot be replaced by CSV-supplied revision metadata. Blank references are insert-only and never overwrite existing observations by name/date.

Preview groups New/Changed/Unchanged/Needs review with readable before/after values and notes. Needs review blocks the complete apply; no silently skipped updates. Apply rechecks freshness and EOS membership, commits atomically with audit and exact retry receipt. Existing source/history and review flags remain available internally. Limits2,000 rows/4MB per file.
