## Behavior

- One Quarter view selector: exact labels **Management Cycle Quarter** and **Calendar Quarter**. Choosing a view or All history loads a complete snapshot, shows its exact range and uses the same filter for history, print and bulk-edit export. Full/year/custom history remains under Filters & exports.
- Both use the existing **Monday reporting anchor**. This preserves calendar browsing behavior when a meeting is moved across quarter/year boundaries. A management cycle beginning Wednesday first includes the following Monday's reporting week. Actual meeting dates and each observation's measurement interval remain unchanged; preceding Monday–Sunday historical intervals are retained. This grouping choice is stated in Edit → Quarter and measurement rules; review it before rollout if Ryan instead wants meeting-date attribution.
- Management cycles require explicit names and effective starts. No Wednesday, calendar-quarter date or historical exception is guessed. Each ends immediately before the next saved start, preventing overlap; the latest remains open until another cycle is defined. Duplicate starts/names/identities and invalid dates reject. Weeks before the first defined cycle show an empty setup state. No hard-delete UI/API for existing cycles.
- Saved cumulative snapshots retain their original interval/basis. They are labeled reported cumulative snapshots. Changing views never derives an alternate total; summing cumulative/rolling snapshots is suppressed in configured summaries. Original definition, value, dates, owner, goal, comments and source/review fields remain untouched. No alternate calendar/management totals can be recovered without suitable underlying data.
- New cycle configuration is a private RLS-protected singleton behind normal EOS permission-checked RPCs. A schedule revision prevents concurrent overwrite, existing begin/finish-write receipts make retry exact, and each change audits its before/after schedule. The global scorecard revision advances so previous import previews/exports become stale; no existing writer or permission predicate is replaced.
- Additive source migration `20261020164305_eos_scorecard_quarter_cycles.sql`; generated using local Supabase CLI. Read-only cycle RPC checks the same scorecard snapshot as the existing read/history APIs. Missing migration produces an explicit setup-unavailable state rather than guessed cycles. Auth errors are not swallowed.
