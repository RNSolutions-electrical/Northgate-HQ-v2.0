# Simple scorecard CSV round trip — Staging only

Ryan approved replacing the technical historical-import controls with Export for bulk editing → edit Value/Notes → Upload edited CSV → readable review → Confirm save. Existing ingestion APIs/history remain, but those controls and shared legacy CSV controls are hidden from the ordinary remote workspace. No XLSX importer, auth configuration, owner/goal assignment, membership grants or Production changes are included.

Contract: [SCORECARD_BULK_CSV_CONTRACT.md](../SCORECARD_BULK_CSV_CONTRACT.md). Eight human-facing columns; HQ supplies protected source details and opaque references automatically. Initial conversion rows may omit references, but can only insert against an unambiguous existing historical definition. Names never authorize overwrites. Original source Date stays distinct from Monday anchor; updates preserve original measurement dates, definition, source/review metadata and protected provenance suffix. Source Review=Needs review is provisional data, not an invalid-row gate. Unknown names/units/intervals or duplicate/stale/tampered rows require review and prevent the entire apply. Blank values/notes preserve existing contents; missing rows do nothing. Percentages use explicit0–100 points; exact decimal text is retained in CSV and human preview.

Four new authenticated EOS RPCs export/preview/apply/recover. Server-only exports bind each reference to the actor, immutable baseline, revision snapshot and7-day expiry. Upload uses stored baselines rather than client revisions; preview expires30minutes, rechecks current state and membership, and any intervening scorecard write invalidates unapplied previews/exports. Apply revalidates and invokes the existing guarded period/observation RPCs in one transaction with source dedupe, metadata, before/after per-record audits and import receipt. Same-ID retry returns the exact completed receipt. No-op re-upload writes no observation or business audit.

Existing metric and observation functions are not replaced; the migration fails closed if their reviewed hashes drift. New private tables have RLS/no direct client privileges. New public endpoints check the normal EOS predicate; no eligibility/security boundary expansion. Recovery reference `sql/eos_bulk_edit_disable.sql` stops only the new writers and leaves receipts/history intact.
