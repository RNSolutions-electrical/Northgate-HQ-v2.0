Ryan requested a New client option in the existing Pursuit Tracker client picker. Broader UI redesign is deferred. Branch codex/eos-pursuit-new-client starts at current Staging d0b3403; this release adds no scorecard/import changes and does not promote anything to Production.

The Client select now includes New client… in new Pursuit, Edit Pursuit and inline Change client. It opens the existing shared client contact workflow with minimal name/company/email/phone fields. The pursuit drawer is suspended while the client drawer is open; its state remains in memory, avoiding two competing modal focus traps. Cancel/close restores the unchanged pursuit. Saving selects the new client in the originating full or inline draft without auto-saving the pursuit. Existing shared contact-card editing retains its full fields and existing persistence route. Explicit textarea labels remain stable when the pursuit drawer remounts.

Persistence remains authenticated client.from('eos_clients') SELECT/INSERT/UPDATE under the existing eos_clients_access policy and audit triggers. No new entity/store, database migration, grants, auth settings or privileged fallback. Required display-name validation and existing database constraints remain. New clients use a stable UUID primary key; uncertain inserts lock the unchanged draft and Recover client save first reads that key, preventing a second insert after lost response. A recovered row must match all submitted fields. A fresh exact normalized-name preflight offers Select existing client explicitly rather than guessing or merging contacts. This is a UI duplicate preflight, not a new database-wide unique-name constraint; existing source-label/primary-key constraints remain unchanged.
